Calibration and Validation Data for Agroecosystem Models

Curated field observations and synthesis evidence for evaluating soil organic carbon (SOC) and greenhouse gas (GHG) responses to agricultural management. This repository supplies evidence and provenance; model configuration, gap-filling, calibration, and validation analyses belong downstream.

What the repository contains

Two complementary evidence streams are maintained:

  • Site observations: measurements, sites, treatments, management histories, methods, and citations in ten committed tables under data/. The report selects 630 SOC-stock and gas-flux records from six California sites; records are not necessarily independent measurements.
  • Synthesis evidence: extracted findings, normalized quantities, selected targets, uncertainty definitions, and inventory reference values under data_raw/statewide_benchmarking/. Sources cover their reported geographic domains, not necessarily California.

SOC practice contrasts are concentrated at Russell Ranch and Salinas; Modesto adds a compost–control N2O contrast. The Delta towers supply flux magnitudes but no curated within-site management contrast. Neither stream alone demonstrates statewide model skill.

The website is a draft evidence guide. Its report describes a selected snapshot and limitations, not completed calibration, independent validation, or acceptance of a model. The data reference documents the exported schema; draft schema proposals are kept separate in the protocol.

Overall workflow

  1. Identify sources. Assemble archived data, papers, supplements, methods, and licenses. Record source locations and unresolved ambiguities.
  2. Curate and review. Enter site datasets in the workbooks configured in 000-config.yml; enter synthesis findings in the synthesis workbook. Workbooks are the curation source of truth.
  3. Export both streams. scripts/ingest.R combines site-workbook tabs into data/*.csv. scripts/ingest_benchmarking.R exports synthesis worksheets into data_raw/statewide_benchmarking/*.csv. Do not hand-edit generated CSVs.
  4. Validate and inspect. Run the schema/key checks and tests below; review warnings, source reconstruction, units, dates, measurement support, and uncertainty. The R validator reports warnings without failing, so a successful exit alone is not approval.
  5. Version a reviewed snapshot. Commit reviewed exports and provenance together when a dataset version is ready. Downstream users read committed CSVs rather than a changing workbook.
  6. Use downstream. Match model outputs to each observation or synthesis target’s units, period, depth, measurement support, comparator, and uncertainty definition. Keep calibration separate from evaluation against independent evidence.

Reported observations are retained with source units and statistics. Documented derived products, including equivalent-soil-mass SOC and normalized synthesis targets, preserve their source and transformation notes. Model-facing imputation and observation operators remain downstream.

Check the data and preview the site

Run from the repository root. Data checks require R with readr, jsonlite, and testthat; site preview requires Quarto.

Rscript scripts/validate.R
Rscript -e 'testthat::test_dir("tests/testthat", stop_on_failure = TRUE)'
quarto render
quarto preview

Workbook access and additional ingestion dependencies are needed only to regenerate exports; see the data reference. Rendering does not ingest workbooks or run models. Preview locally before publishing; these commands do not publish the site.
