This reference was moved out of the repository README on 2026-09-30, when the README became the home page of this site. The README had fallen behind the repository in places, so the tables and lists below were brought up to date with develop 900ffd2 on that date. The changes are listed at the end. For fields, types and keys, datapackage.json remains the authority.

Overview

Datasets describe field experiments where a soil carbon or greenhouse gas response was measured against a control, so a model can be tested on two things at once: absolute value, and treatment difference (practice change signal that policy applications care about).

Key features:

  • Model agnostic. Observations stay in reported units with no model specific transformation. Mapping to model state variables happens downstream.
  • Long format observations, one row per dataset, site, treatment, replicate, time window, and variable, at replicate level where source archive provides it.
  • Stable text keys (dataset_id, site, treatment_id, citation) rather than database identifiers.
  • Per row provenance through fill_status, recording which source file each value came from.
  • Source stated date ranges in min_date and max_date; point dates are never invented.
  • Named treatment contrasts in treatment_pairs, so practice change validation (compost vs no compost, cover crop vs none, organic vs conventional) is a first class query.
  • Coverage matrix tracking which system, contrast, and target cells are filled, so gaps stay explicit.

The statewide synthesis evidence is kept apart from these tables, in data_raw/statewide_benchmarking/. Its README describes the files, and Part B of the report describes the evidence.

Data flow

Curation happens in Google Sheet workbooks, which are the source of truth. CSVs in data/ and data_raw/statewide_benchmarking/ are generated exports and must not be hand edited.

  1. The workbooks hold the curated tables and are edited and reviewed there. 000-config.yml lists the three dataset workbooks: Salinas and Modesto, Russell Ranch, and the AmeriFlux Delta towers.
  2. scripts/ingest.R pulls each workbook tab to data/<tab>.csv, stacking the tab across all three workbooks.
  3. scripts/validate.R checks data/ against datapackage.json.
  4. scripts/ingest_benchmarking.R pulls the synthesis and meta-analysis evidence workbook into data_raw/statewide_benchmarking/, one CSV per worksheet except its README. With --check it compares the workbook with the committed CSVs and writes nothing.
  5. Downstream consumers read committed CSVs.

CSVs are committed so consumers read a stable, documented snapshot. A workbook can keep changing without a commit per edit; CSVs are regenerated and committed when a dataset version is ready.

Datasets

Each site level dataset has a folder under data_raw/ whose data_entry_report.md records its provenance and curation decisions. Replicate level values come from a public archive wherever one provides them; companion analysis papers supply methods and cross checks. Each dataset group is curated in its own workbook, and ingest stacks each tab across all workbooks into one CSV per table.

The annual NEE and tower CH4 rows at the three Delta sites, and the annual chamber rows taken from publication tables at the two Bouldin sites, carry the upstream product or publication as their dataset_id, for example ameriflux_fluxnet_1f_us_bi1_v1_3_r1, fluxnet_ch4_community_product_v1_appendix_b_v2 or publication_anthony_2023_table_1. data/observations.csv therefore holds 14 dataset_id values in all.

white_salinas_2020

Organic vegetable rotation (romaine lettuce, broccoli) with winter cover crops and compost. Randomized complete block, 4 blocks, so block level is replicate level here. Companion analysis paper focuses on 5 systems (those with optimal cover crop seeding rates); workbook carries all 8 from archive. SOC stock is concentration times bulk density times depth (0 to 30 cm), with bulk density measured only at end of Years 3 and 7 and propagated by equivalent soil mass, so core_sample method row carries that propagation rule. A large Year 0 to Year 1 SOC drop appears across all systems including no compost control, and is documented in source.

nichols_modesto_2024

Long term compost orchard with high frequency low concentration drip fertigation (about 195 kg N ha-1 across 14 events). N2O measured by closed static chamber on 9 dates (Dec 2018 to Aug 2019), 3 replicate arrays per treatment, upscaled to emitter level. Soil total C, total N, and bulk density are single timepoint (August 2019), so this dataset supports N2O magnitude and contrast validation but not a SOC trajectory.

Coverage

data/coverage.csv crosses system and treatment contrast against each target, split into magnitude and treatment contrast, for SOC change, N2O, CH4 and woody biomass. Target cells are coded 1 where current datasets cover them and 0 where they are tracked gaps. The planning matrix, with the SOC change and N2O columns and 1 shown as yes:

The matrix predates the Russell Ranch, AmeriFlux Delta and Bouldin chamber datasets. Russell Ranch adds SOC change magnitude and contrasts on annual row crops, among them cover cropping, compost against synthetic fertiliser, rotation and irrigation (A7). N2O is covered at three sites (nichols_modesto_2024 static chamber; anthony_bouldin_2024 automated chamber at US-Bi2 and US-Bi1) and CH4 at three (tower annual budgets for US-Twt, US-Bi1 and US-Bi2, plus chamber CH4 at the two Bouldin sites). Chamber and tower values are different measurement supports and are not interchangeable. A4 in the report shows the target records by site and variable.

Because ingest stacks the coverage tab from every workbook, the file holds the matrix and its MVP coverage guidance twice, the second copy with every SOC, N2O and CH4 cell 0, followed by six rows of record counts for CH4_flux and NEE at US-Bi1, US-Bi2 and US-Twt.

Conventions

  • Stable text keys. A site key is physical location only; it does not encode treatment, replicate, or date. Treatment keys (socs_sys1, compost, no_compost) stay stable across a dataset.
  • Long format, replicate level. Where a paper has a companion data archive, ingest replicate level values from archive; summary tables in analysis paper are for cross checking, not primary fill source.
  • Dates. Record source stated range in min_date and max_date. An exact date sets both equal; a stated month or season bounds interval; an unknown date stays blank with reason in notes. Never invent a day of year.
  • Statistics. Store reported statistic (n, statname, stat) as given. Statistic conversion (standard deviation to standard error, and similar) is a downstream step, not curation.
  • Basis. Methods state dry vs wet basis (prefer dry) and volumetric vs mass basis. Amendment rates carry their basis in units.
  • fill_status. Provenance code for each value. Codes in current data: FILLED_DATA_PUBLICATION, SCRIPTED_DERIVED, FILLED_ZOTERO_XLSX, FILLED_DATASET, FILLED_SITE_DATA_XLSX, REPORTED_DIRECT, FILLED_PUBLICATION_TABLE and FILLED_PUBLICATION_TEXT. datapackage.json also allows FILLED_S1_TABLE and FILLED_USDA_SOIL_XLSX. Additional codes (PAPER_TEXT, NEEDS_FILL, MISSING_IN_SOURCE) are reserved for rows still being curated.

Validation

scripts/validate.R checks every generated data/*.csv against datapackage.json. It runs in warn mode: missing columns, empty keys, broken foreign keys, and odd dates warn but do not stop, so a workbook in progress still passes. It needs only base R plus jsonlite and readr.

Rscript scripts/validate.R

Tests under tests/testthat/ run the same checks via testthat, plus checks on the statewide evidence; they also need testthat and here. Tables not yet generated are skipped, so a fresh clone passes.

Rscript -e 'testthat::test_dir("tests/testthat")'

CI (.github/workflows/validate.yml) runs both, plus frictionless validate datapackage.json, on every pull request and on pushes to main.

Usage

Load a table

library(readr)
obs <- read_csv("data/observations.csv", show_col_types = FALSE)

# replicate level SOC stock
subset(obs, variable == "SOC_stock_Mg_ha" & observation_level == "replicate")

Pull a treatment contrast

pairs <- read_csv("data/treatment_pairs.csv", show_col_types = FALSE)

# contrasts flagged for validation (e.g. compost vs no compost)
subset(pairs, use_for_validation == TRUE)

Regenerate the snapshot from the workbooks

# the workbook ids are in 000-config.yml; authenticate once
# interactively with googlesheets4::gs4_auth(), then
source("scripts/ingest.R")

The statewide evidence has its own script. Set CCMMF_SHEETS_EMAIL to the Google account that can read the evidence workbook.

Rscript scripts/ingest_benchmarking.R --check   # compare the workbook with the committed CSVs
Rscript scripts/ingest_benchmarking.R           # regenerate them
